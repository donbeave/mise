## Findings

### What is the official formula state model?

- Homebrew has distinct state predicates, not one installed flag: `latest_version_installed?` means the selected current-version Cellar directory exists and is non-empty; `any_version_installed?` means an installed prefix contains `INSTALL_RECEIPT.json`; `linked?` means the `var/homebrew/linked/<name>` record exists; `optlinked?` means `opt/<name>` is a symlink. Selection of “any installed” prefers a live opt target, then the last installed prefix. — [`Library/Homebrew/formula.rb:942-1076`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/formula.rb#L942-L1076), [`Library/Homebrew/formula.rb:2805-2825`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/formula.rb#L2805-L2825), Homebrew/brew commit `24f8780838c054a92ebf58b09455acbb236731bd` (confidence: HIGH)
- Dependency readiness is stricter than formula presence: `Dependency#installed?` requires an existing opt prefix, then accepts the latest version or checks bottle-provided minimum version/revision/compatibility metadata; `satisfied?` additionally requires requested build options. Thus a receipt-bearing keg, an opt-active dependency, and a publicly linked formula are separate official states. — [`Library/Homebrew/dependency.rb:62-139`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/dependency.rb#L62-L139), Homebrew/brew commit `24f8780838c054a92ebf58b09455acbb236731bd` (confidence: HIGH)

### What are the receipt semantics and root/dependency ownership rules?

- The receipt is `<keg>/INSTALL_RECEIPT.json`. A new formula receipt records Homebrew version, API origin flags, install time, architecture, source tap and tap commit, build-system information, source/spec/version data, aliases, bottle/source status, options, and serialized runtime dependencies. — [`Library/Homebrew/tab.rb:18-59`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/tab.rb#L18-L59), [`Library/Homebrew/tab.rb:92-108`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/tab.rb#L92-L108), [`Library/Homebrew/tab/tab.rb:70-111`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/tab/tab.rb#L70-L111), [`Library/Homebrew/tab/tab.rb:367-419`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/tab/tab.rb#L367-L419), Homebrew/brew commit `24f8780838c054a92ebf58b09455acbb236731bd` (confidence: HIGH)
- Root-versus-dependency ownership is `installed_on_request`. Missing values default to false but presence is tracked; unknown receipt keys are ignored, explicitly including the long-removed `installed_as_dependency`. Autoremove only selects a receipt whose `installed_on_request` field is explicitly present and false, after recursively excluding formulae still needed by formula/cask dependents; poured bottles retain runtime deps, while source builds also retain declared build deps. — [`Library/Homebrew/tab.rb:25-89`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/tab.rb#L25-L89), [`Library/Homebrew/utils/autoremove.rb:10-18`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/utils/autoremove.rb#L10-L18), [`Library/Homebrew/utils/autoremove.rb:51-108`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/utils/autoremove.rb#L51-L108), Homebrew/brew commit `24f8780838c054a92ebf58b09455acbb236731bd` (confidence: HIGH)

### What is the official install flow?

- Formula install locks the formula, applies disabled/forbidden/license/sanity/conflict checks, resolves and installs dependencies first, then pours a usable bottle or builds from source. A source install stores the exact formula Ruby in `<keg>/.brew`, updates the receipt's requested/dependency ownership, and then `finish` performs linking, service installation, dynamic-link repair, global post-install, `.bottle/etc`/`.bottle/var` restoration, formula post-install, and a final runtime-dependency receipt rewrite. — [`Library/Homebrew/formula_installer.rb:306-365`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/formula_installer.rb#L306-L365), [`Library/Homebrew/formula_installer.rb:550-645`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/formula_installer.rb#L550-L645), [`Library/Homebrew/formula_installer.rb:987-1034`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/formula_installer.rb#L987-L1034), Homebrew/brew commit `24f8780838c054a92ebf58b09455acbb236731bd` (confidence: HIGH)
- `brew install` treats an already-linked outdated stable formula as an upgrade unless install-upgrade is disabled; after each formula it runs install cleanup, and a non-build exception for one formula marks failure but does not stop the remaining batch. — [`Library/Homebrew/install.rb:349-406`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/install.rb#L349-L406), Homebrew/brew commit `24f8780838c054a92ebf58b09455acbb236731bd` (confidence: HIGH)

### How are dependencies resolved and installed?

- Homebrew recursively expands dependencies with cycle protection, resolves aliases/renames to the formula actually loaded, and returns dependencies before their dependent. Optional and recommended dependencies are pruned unless selected by the dependent's build options. During installation, build/test dependencies are retained only when needed for a source build or requested test, while bottle receipt metadata supplies minimum runtime versions/revisions and the bottle's build OS for variation-sensitive resolution. — [`Library/Homebrew/dependency.rb:169-250`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/dependency.rb#L169-L250), [`Library/Homebrew/formula_installer.rb:770-806`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/formula_installer.rb#L770-L806), [`Library/Homebrew/formula_installer.rb:368-388`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/formula_installer.rb#L368-L388), Homebrew/brew commit `24f8780838c054a92ebf58b09455acbb236731bd` (confidence: HIGH)
- Replacing an installed dependency is transactional at keg granularity: Homebrew unlinks its active keg, renames the installed current keg to `.tmp`, preserves `installed_on_request`, installs and finishes the replacement, restores and relinks the old keg on failure, and deletes the temporary old keg on success. It refuses an already-installed dependency whose receipt names a different tap. — [`Library/Homebrew/formula_installer.rb:879-948`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/formula_installer.rb#L879-L948), Homebrew/brew commit `24f8780838c054a92ebf58b09455acbb236731bd` (confidence: HIGH)

### How are bottles selected, verified, poured, and relocated?

- Bottle use requires a matching bottle and compatible location, no forced source/build-bottle/interactive/compiler/options condition, and a satisfied formula-specific `pour_bottle?`; otherwise Homebrew builds from source. The host tag combines OS and architecture; macOS accepts the exact tag, `all`, or an older same-architecture macOS tag not newer than the host. — [`Library/Homebrew/formula_installer.rb:255-303`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/formula_installer.rb#L255-L303), [`Library/Homebrew/utils/bottles.rb:12-28`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/utils/bottles.rb#L12-L28), [`Library/Homebrew/utils/bottles.rb:341-397`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/utils/bottles.rb#L341-L397), [`Library/Homebrew/extend/os/mac/utils/bottles.rb:8-59`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/extend/os/mac/utils/bottles.rb#L8-L59), Homebrew/brew commit `24f8780838c054a92ebf58b09455acbb236731bd` (confidence: HIGH)
- A bottle object takes its checksum from the selected tag and delegates fetch with integrity verification. Pour stages/extracts under the formula rack, loads the bottle tab, rewrites install-local receipt fields, then replaces path placeholders. `:any` requires text and binary relocation; `:any_skip_relocation` still requires text relocation. On Linux, skip-binary-relocation is honored only when the bottle tab reports Homebrew 5.1.15 or newer. — [`Library/Homebrew/bottle.rb:109-145`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/bottle.rb#L109-L145), [`Library/Homebrew/formula_installer.rb:1582-1648`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/formula_installer.rb#L1582-L1648), [`Library/Homebrew/bottle_specification.rb:7-15`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/bottle_specification.rb#L7-L15), [`Library/Homebrew/extend/os/linux/bottle_specification.rb:7-11`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/extend/os/linux/bottle_specification.rb#L7-L11), Homebrew/brew commit `24f8780838c054a92ebf58b09455acbb236731bd` (confidence: HIGH)
- Relocation replaces Homebrew prefix/Cellar/repository/library and selected interpreter placeholders in text; macOS also rewrites Mach-O IDs, dependencies, and rpaths and re-signs modified binaries, while Linux rewrites dynamic ELF rpaths/interpreters except glibc. — [`Library/Homebrew/keg_relocate.rb:143-201`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/keg_relocate.rb#L143-L201), [`Library/Homebrew/extend/os/mac/keg_relocate.rb:27-53`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/extend/os/mac/keg_relocate.rb#L27-L53), [`Library/Homebrew/extend/os/linux/keg_relocate.rb:14-73`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/extend/os/linux/keg_relocate.rb#L14-L73), Homebrew/brew commit `24f8780838c054a92ebf58b09455acbb236731bd` (confidence: HIGH)

### What are the source and tap semantics?

- Core normally loads metadata from Homebrew's aggregate API and per-formula JSON. When source Ruby is needed, Homebrew requires a repository-relative path, fetches it from the formula's tap at `tap_git_head`, instantiates that Ruby through Formulary, and source build runs it in a separate Ruby process with formula-scoped sandbox write/network rules; an empty keg is an error. — [`Library/Homebrew/api/formula.rb:18-38`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/api/formula.rb#L18-L38), [`Library/Homebrew/api/formula.rb:49-116`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/api/formula.rb#L49-L116), [`Library/Homebrew/formulary.rb:905-955`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/formulary.rb#L905-L955), [`Library/Homebrew/formula_installer.rb:1130-1193`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/formula_installer.rb#L1130-L1193), Homebrew/brew commit `24f8780838c054a92ebf58b09455acbb236731bd` (confidence: HIGH)
- A non-core tap is installed statefully as a local Git checkout at its tap directory, with the requested/default remote and allow/forbid checks; formula Ruby is discovered under `Formula`, `HomebrewFormula`, or the tap root and recursively under the formula directory, then loaded by `FromTapLoader`. Core is exceptional: API mode avoids requiring the core checkout. — [`Library/Homebrew/tap.rb:376-410`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/tap.rb#L376-L410), [`Library/Homebrew/tap.rb:511-517`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/tap.rb#L511-L517), [`Library/Homebrew/tap.rb:639-761`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/tap.rb#L639-L761), [`Library/Homebrew/tap.rb:950-1041`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/tap.rb#L950-L1041), [`Library/Homebrew/formulary.rb:702-766`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/formulary.rb#L702-L766), [`Library/Homebrew/tap/core_tap.rb:23-28`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/tap/core_tap.rb#L23-L28), Homebrew/brew commit `24f8780838c054a92ebf58b09455acbb236731bd` (confidence: HIGH)

### What are the link and mutation-ownership boundaries?

- `Keg#link` first creates/replaces the formula's opt record, then links selected `etc`, `bin`, `sbin`, `include`, `share`, `lib`, and framework paths into the prefix, and creates `var/homebrew/linked/<name>` only at the end. Default public-link behavior preserves an identical link, removes dangling symlinks, expands conflicts only when a symlink resolves into another Cellar keg, and raises on an occupied foreign destination unless explicit overwrite applies. Any `LinkError` triggers unlink of the partial link set. — [`Library/Homebrew/keg.rb:490-580`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/keg.rb#L490-L580), [`Library/Homebrew/keg.rb:615-629`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/keg.rb#L615-L629), [`Library/Homebrew/keg.rb:704-780`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/keg.rb#L704-L780), Homebrew/brew commit `24f8780838c054a92ebf58b09455acbb236731bd` (confidence: HIGH)
- Unlink removes a public symlink only when it resolves to the corresponding source inside that exact keg, then removes the linked-keg record. Keg uninstall removes the keg/rack and removes opt/linked records only when they target that keg. The opt-link creation path itself deletes an existing path at the formula's opt/alias record before replacement. — [`Library/Homebrew/keg.rb:323-393`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/keg.rb#L323-L393), [`Library/Homebrew/keg.rb:615-629`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/keg.rb#L615-L629), Homebrew/brew commit `24f8780838c054a92ebf58b09455acbb236731bd` (confidence: HIGH)
- Homebrew expects the prefix/Cellar/cache/locks/logs/repository and public link directories to be writable by the invoking user and refuses ordinary mutating execution as root outside enumerated container/CI/service exceptions because formula build scripts retain full privileges. — [`Library/Homebrew/keg.rb:143-185`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/keg.rb#L143-L185), [`Library/Homebrew/brew.sh:159-200`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/brew.sh#L159-L200), Homebrew/brew commit `24f8780838c054a92ebf58b09455acbb236731bd` (confidence: HIGH)

### How do shared `.bottle/etc` and `.bottle/var` behave?

- Formula `etc`/`pkgetc` and `var` point outside the Cellar and persist across upgrades. While building a bottle, newly created shared files are copied under `<keg>/.bottle`; on normal finish, Homebrew copies `.bottle/etc` and `.bottle/var` into the live prefix through `InstallRenamed`. — [`Library/Homebrew/formula.rb:1349-1374`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/formula.rb#L1349-L1374), [`Library/Homebrew/formula.rb:1430-1434`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/formula.rb#L1430-L1434), [`Library/Homebrew/formula_installer.rb:535-546`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/formula_installer.rb#L535-L546), [`Library/Homebrew/formula.rb:1587-1597`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/formula.rb#L1587-L1597), Homebrew/brew commit `24f8780838c054a92ebf58b09455acbb236731bd` (confidence: HIGH)
- Config replacement is content-sensitive: absent or byte-identical destinations install normally; an untouched live config identical to an older keg's bottled default may advance; otherwise the new file is written as `*.default`. Normal uninstall deliberately leaves `pkgetc` and likely formula-named `etc` state in place and reports it. — [`Library/Homebrew/install_renamed.rb:43-73`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/install_renamed.rb#L43-L73), [`Library/Homebrew/uninstall.rb:70-107`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/uninstall.rb#L70-L107), Homebrew/brew commit `24f8780838c054a92ebf58b09455acbb236731bd` (confidence: HIGH)

### What is the post-install lifecycle, including OpenSSL/CA trust state?

- Unless explicitly skipped or building a bottle, finish restores `.bottle/etc`/`.bottle/var` and runs declarative `post_install_steps` and/or Ruby `post_install` in a separate sandboxed process with isolated HOME/PATH/sensitive environment and declared prefix write/network allowances. `brew postinstall` reruns shared-file restoration and the same post-install path. — [`Library/Homebrew/formula_installer.rb:1001-1017`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/formula_installer.rb#L1001-L1017), [`Library/Homebrew/formula_installer.rb:1390-1427`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/formula_installer.rb#L1390-L1427), [`Library/Homebrew/formula.rb:1600-1660`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/formula.rb#L1600-L1660), [`Library/Homebrew/cmd/postinstall.rb:15-31`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/cmd/postinstall.rb#L15-L31), Homebrew/brew commit `24f8780838c054a92ebf58b09455acbb236731bd` (confidence: HIGH)
- Current `ca-certificates` installs Mozilla's bundle in the keg and a post-install helper; its required declarative step runs that helper to atomically generate `etc/ca-certificates/cert.pem`, merging valid unique system and Mozilla certificates on macOS/Linux when system inputs exist, with Mozilla-only fallback on Linux. ### What is the official upgrade flow?

- Upgrade orders keg-only formulae before non-keg-only formulae and topologically orders the selected formulae. It carries forward the active keg's linked state, `installed_on_request`, and bottle-build status; unlinks old active kegs before installation; installs and finishes the new keg; and restores previous links if the new current version is absent. Separate cleanup rules exclude linked, pinned, or `.keepme`-referenced kegs. — [`Library/Homebrew/upgrade.rb:65-159`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/upgrade.rb#L65-L159), [`Library/Homebrew/upgrade.rb:606-663`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/upgrade.rb#L606-L663), [`Library/Homebrew/install.rb:593-626`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/install.rb#L593-L626), [`Library/Homebrew/formula.rb:3630-3670`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/formula.rb#L3630-L3670), Homebrew/brew commit `24f8780838c054a92ebf58b09455acbb236731bd` (confidence: HIGH)

### What is the official uninstall flow?
