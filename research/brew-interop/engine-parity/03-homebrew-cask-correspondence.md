Questions: For the cask capabilities already implemented by mise's `brew-cask:` manager and reachable through `mise bootstrap`, what are the corresponding official Homebrew Ruby semantics for metadata and artifacts, fetching and checksums, installed-state detection, receipt/version topology, ownership, install/reinstall/adoption, upgrade and `auto_updates` drift, uninstall/zap/prune/cleanup, dependencies, platform/architecture/language selection, conflicts, and failure boundaries?

Informs: mise-bootstrap-brew-interop

Method: read-only source comparison of https://github.com/Homebrew/brew.git @ `24f8780838c054a92ebf58b09455acbb236731bd` and https://github.com/jdx/mise.git @ `6f52dcdf99e282ef7a7db68c81301fa4618d0f79`, both shallow-cloned on 2026-08-22. Scope was derived from the registered `BrewCaskManager`, its bootstrap driver, and its cask parser/lifecycle paths; Homebrew-only cask features outside those paths were excluded. Repository content was treated as data. No agent-directed embedded instructions were found in cited source files.

Vetted: 2026-08-22

### How does official Homebrew interpret cask API metadata and artifacts?

- Homebrew does not consume the public cask JSON as an already-final machine-specific record. Its API loader first merges the current OS/architecture variation, builds language-specific structs, converts dependency/artifact arguments, then localises again with configured languages before instantiating Ruby DSL artifacts. Mise directly deserializes a narrower `Cask` record and manually parses artifact JSON; no `variations`, `supported_platforms`, or `language_variations` field exists in that record. — [Homebrew/brew `Library/Homebrew/api/cask/cask_struct_generator.rb:11-35`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/api/cask/cask_struct_generator.rb#L11-L35), [Homebrew/brew `Library/Homebrew/cask/cask_loader.rb:508-567`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/cask/cask_loader.rb#L508-L567), [jdx/mise `src/system/packages/brew/cask.rs:44-87`](https://github.com/jdx/mise/blob/6f52dcdf99e282ef7a7db68c81301fa4618d0f79/src/system/packages/brew/cask.rs#L44-L87), [jdx/mise `src/system/packages/brew/cask.rs:898-938`](https://github.com/jdx/mise/blob/6f52dcdf99e282ef7a7db68c81301fa4618d0f79/src/system/packages/brew/cask.rs#L898-L938) (confidence: HIGH)

- For overlapping artifact kinds, Homebrew converts every API artifact tuple back into its DSL method and stores typed artifacts in a sorted `ArtifactSet`; mise recognizes `app`, `binary`, `command_wrapper`, `pkg`, script `installer`, generic `artifact`, `font`, declared/generated completions, and structured pre/postflight steps, and fails the cask on any remaining install artifact type or on no supported install artifact. — [Homebrew/brew `Library/Homebrew/api/cask/cask_struct_generator.rb:145-161`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/api/cask/cask_struct_generator.rb#L145-L161), [Homebrew/brew `Library/Homebrew/cask/cask_loader.rb:565-578`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/cask/cask_loader.rb#L565-L578), [Homebrew/brew `Library/Homebrew/cask/artifact_set.rb:5-22`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/cask/artifact_set.rb#L5-L22), [jdx/mise `src/system/packages/brew/cask.rs:4944-5027`](https://github.com/jdx/mise/blob/6f52dcdf99e282ef7a7db68c81301fa4618d0f79/src/system/packages/brew/cask.rs#L4944-L5027) (confidence: HIGH)

### What are the corresponding fetch, checksum, and staging semantics?

- Homebrew builds a `URL` from the full cask URL specs, downloads through the selected strategy, quarantines the cached download, verifies integrity, detects/extracts the declared or inferred container, and propagates quarantine to extracted contents. Mise handles `.git` URLs with clone plus `branch`/`only_path`; otherwise it downloads an archive, removes `com.apple.quarantine`, requires either a SHA-256 or `no_check`, then extracts by its own format detection. Checksum acceptance overlaps, but quarantine semantics are opposite. — [Homebrew/brew `Library/Homebrew/cask/download.rb:35-77`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/cask/download.rb#L35-L77), [Homebrew/brew `Library/Homebrew/cask/download.rb:92-129`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/cask/download.rb#L92-L129), [jdx/mise `src/system/packages/brew/cask.rs:973-1023`](https://github.com/jdx/mise/blob/6f52dcdf99e282ef7a7db68c81301fa4618d0f79/src/system/packages/brew/cask.rs#L973-L1023), [jdx/mise `src/system/packages/brew/cask.rs:1026-1094`](https://github.com/jdx/mise/blob/6f52dcdf99e282ef7a7db68c81301fa4618d0f79/src/system/packages/brew/cask.rs#L1026-L1094) (confidence: HIGH)

- Homebrew requires a platform SHA when the cask came from API data or has system conditionals; `sha256 :no_check` suppresses a checksum, and a missing checksum is tolerated only for non-official casks with a warning when the stricter requirement does not apply. Mise rejects missing `sha256` for every archive and accepts literal `no_check`. — [Homebrew/brew `Library/Homebrew/cask/download.rb:42-76`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/cask/download.rb#L42-L76), [Homebrew/brew `Library/Homebrew/cask/download.rb:214-249`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/cask/download.rb#L214-L249), [jdx/mise `src/system/packages/brew/cask.rs:1046-1051`](https://github.com/jdx/mise/blob/6f52dcdf99e282ef7a7db68c81301fa4618d0f79/src/system/packages/brew/cask.rs#L1046-L1051) (confidence: HIGH)

- For Git `only_path`, Homebrew uses sparse checkout but keeps the path as the base for artifact source resolution; mise moves that directory's children to its extraction root. Both make artifact-relative lookup land in the selected subtree, but their staged directory topology differs. — [Homebrew/brew `Library/Homebrew/download_strategy/git_download_strategy.rb:10-24`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/download_strategy/git_download_strategy.rb#L10-L24), [Homebrew/brew `Library/Homebrew/download_strategy/git_download_strategy.rb:303-314`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/download_strategy/git_download_strategy.rb#L303-L314), [Homebrew/brew `Library/Homebrew/cask/artifact/relocated.rb:56-62`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/cask/artifact/relocated.rb#L56-L62), [jdx/mise `src/system/packages/brew/cask.rs:1003-1023`](https://github.com/jdx/mise/blob/6f52dcdf99e282ef7a7db68c81301fa4618d0f79/src/system/packages/brew/cask.rs#L1003-L1023) (confidence: HIGH)

### How does Homebrew detect installation, and what is its native receipt/version topology?

- Homebrew's installed predicate is receipt-metadata based, not live-artifact based: `Cask#installed?` requires an installed caskfile, found only under `Caskroom/<token>/.metadata/<version>/<timestamp>/Casks/<token>.{json,internal.json,rb}`; installed version is derived from that metadata path. A surviving app or `Caskroom/<token>/<version>` directory without this caskfile is not sufficient. — [Homebrew/brew `Library/Homebrew/cask/cask.rb:246-252`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/cask/cask.rb#L246-L252), [Homebrew/brew `Library/Homebrew/cask/caskroom.rb:41-69`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/cask/caskroom.rb#L41-L69), [Homebrew/brew `Library/Homebrew/cask/metadata.rb:12-59`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/cask/metadata.rb#L12-L59) (confidence: HIGH)

- Homebrew stages payload at `Caskroom/<token>/<version>`, saves the selected cask definition in the timestamped `Casks` directory, and writes `Caskroom/<token>/.metadata/INSTALL_RECEIPT.json` containing source version/path, uninstall artifacts, and runtime dependencies. — [Homebrew/brew `Library/Homebrew/cask/dsl.rb:671-680`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/cask/dsl.rb#L671-L680), [Homebrew/brew `Library/Homebrew/cask/installer.rb:570-610`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/cask/installer.rb#L570-L610), [Homebrew/brew `Library/Homebrew/cask/tab.rb:29-42`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/cask/tab.rb#L29-L42), [Homebrew/brew `Library/Homebrew/tab.rb:18-18`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/tab.rb#L18) (confidence: HIGH)

- Mise shares `Caskroom/<token>/<version>` but records ownership in `<version>/.mise-cask.toml`, including target paths/fingerprints, package IDs, `auto_updates`, and prune-safety fields. ### What concrete ownership and cross-recognition rules exist?

- Mise treats any `.metadata` entry under the canonical token directory as Homebrew ownership: install refuses before mutation and rechecks under its Caskroom lock; prune also skips such a token. ### What are Homebrew install, reinstall, and adoption semantics?

- Homebrew normal install partitions native-receipted casks from new casks, installs only new ones directly, and sends installed casks through upgrade unless install-upgrade is disabled. Its explicit reinstall path creates installers with `reinstall: true`; the installer fetches first, forcibly uninstalls the existing cask, stages the new cask, installs artifacts, then writes the receipt. Mise has no forced same-version reinstall operation in this manager: current-version installs are no-ops, and `upgrade` delegates to the same install convergence path. — [Homebrew/brew `Library/Homebrew/cmd/install.rb:230-238`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/cmd/install.rb#L230-L238), [Homebrew/brew `Library/Homebrew/cmd/install.rb:455-491`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/cmd/install.rb#L455-L491), [Homebrew/brew `Library/Homebrew/cask/reinstall.rb:42-80`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/cask/reinstall.rb#L42-L80), [Homebrew/brew `Library/Homebrew/cask/installer.rb:171-200`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/cask/installer.rb#L171-L200), [jdx/mise `src/system/packages/brew/cask.rs:442-447`](https://github.com/jdx/mise/blob/6f52dcdf99e282ef7a7db68c81301fa4618d0f79/src/system/packages/brew/cask.rs#L442-L447), [jdx/mise `src/system/packages/brew/cask.rs:888-895`](https://github.com/jdx/mise/blob/6f52dcdf99e282ef7a7db68c81301fa4618d0f79/src/system/packages/brew/cask.rs#L888-L895) (confidence: HIGH)

- Homebrew `--adopt` is artifact-level takeover, not import of another manager's receipt. For a moved artifact with an occupied target, non-`auto_updates` adoption compares bundle short/long versions when possible, otherwise recursive content; `auto_updates` skips that equality check. - Mise's similarly named `adopt` is narrower and different: it is used only when mise has no installed version; non-`auto_updates` app bundles must have an identical full target fingerprint, while `auto_updates` skips verification; adopted apps are recorded as metadata-only rather than staged as a Caskroom symlink. Both systems leave the live target in place, but their proof and Caskroom representation differ. — [jdx/mise `src/system/packages/brew/cask.rs:523-528`](https://github.com/jdx/mise/blob/6f52dcdf99e282ef7a7db68c81301fa4618d0f79/src/system/packages/brew/cask.rs#L523-L528), [jdx/mise `src/system/packages/brew/cask.rs:1255-1294`](https://github.com/jdx/mise/blob/6f52dcdf99e282ef7a7db68c81301fa4618d0f79/src/system/packages/brew/cask.rs#L1255-L1294), [jdx/mise `src/system/packages/brew/cask.rs:1327-1342`](https://github.com/jdx/mise/blob/6f52dcdf99e282ef7a7db68c81301fa4618d0f79/src/system/packages/brew/cask.rs#L1327-L1342), [jdx/mise `src/system/packages/brew/cask.rs:6680-6698`](https://github.com/jdx/mise/blob/6f52dcdf99e282ef7a7db68c81301fa4618d0f79/src/system/packages/brew/cask.rs#L6680-L6698) (confidence: HIGH)

### How do upgrade, `auto_updates`, and version drift correspond?

- Homebrew's baseline outdated rule compares native receipt version with current cask version. `version :latest` upgrades only when greedy/latest policy requests it and the downloaded SHA changes. For `auto_updates`, non-greedy checks normally skip receipt-version drift unless the environment enables auto-update cask upgrades; when enabled, Homebrew inspects the live app's `Info.plist` versions and upgrades only when the live bundle is behind. — [Homebrew/brew `Library/Homebrew/cask/cask.rb:431-452`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/cask/cask.rb#L431-L452), [Homebrew/brew `Library/Homebrew/cask/cask.rb:772-801`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/cask/cask.rb#L772-L801), [Homebrew/brew `Library/Homebrew/cask/cask.rb:815-855`](https://github.com/Homebrew/brew/blob/24f8780838c054a92ebf58b09455acbb236731bd/Library/Homebrew/cask/cask.rb#L815-L855) (confidence: HIGH)

- Named Homebrew casks are checked with `greedy: true`, so explicit `brew upgrade <cask>`/install-upgrade can upgrade `auto_updates` or `latest` casks despite the default bulk-upgrade policy.
