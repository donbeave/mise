## Dependency notes

- 002 requires 001: read-side recognition parses cask `.metadata` through
  the schema-strict receipt module.
- 003 requires 002: the ownership guard is deleted only once status already
  recognizes Homebrew state (sequencing rule from the design doc — an
  interim build must never overwrite Homebrew state with the old mise-only
  format).
- 005 requires 003: backfill writes the same receipt set the write side
  produces.
- 006 requires 003 and 004: teardown consumes the truthful
  `uninstall_artifacts` and receipt state those plans write.
- 007 requires 003, 004, 006: the differential oracle verifies install and
  removal parity end to end; parts of its harness may land early in reduced
  form for 003/004 verification.
- 002 alone fixes the production Codex bootstrap failure (status/install
  contradiction) and must not depend on write-side changes.

## Standing constraints (from the design document — apply to every plan)

- Production mise never executes the `brew` CLI. Real `brew` runs only
  inside tests as the differential oracle.
- Every receipt field written must be truthful; no placeholders, no
  synthetic empty tabs.
- Version strings are opaque — no semver sorting or newest-version
  inference anywhere (repository-wide rule, see AGENTS.md "DO NOT ASSUME
  SEMVER").
- No new mise CLI/config surface.
- Never run destructive tests against a developer's real installed apps.
- No `#[allow(clippy::...)]` exclusions; refactor until clippy passes.
